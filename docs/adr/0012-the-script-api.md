# API скриптов — это функции команд, а версия задаётся путём в `require`

Против API скриптов ([ADR-0011](0011-a-command-is-a-script.md)) пишут люди и агенты, о которых `ytrack` ничего не
знает. Здесь решено, как устроен API и как менять его, не ломая написанные скрипты.

## Решение

- **`ytrack/v<N>` экспортирует по объекту на команду с функцией на каждую подкоманду,** а кроме них `fail`,
  `warn`, `address`, `fs` и `http`.
- **Функция команды принимает аргументы и флаги команды в грамматике CLI:** позиционные в том же порядке, за ними
  объект с ключами — именами флагов, как они пишутся после `--`. Лишний ключ, значение не того типа и пропущенный
  обязательный параметр дают `script_failed`.
- **У функций нет значений по умолчанию.** Параметр, у которого у команды есть значение по умолчанию, у функции
  обязателен, потому что поля по умолчанию должны меняться, не меняя ответ API.
- **Ошибка функции команды бросается объектом с полями `code`, `message`, `details` и `wrote`,** где `wrote` — мог ли
  инстанс измениться. Непойманная ошибка печатается как есть.
- **Вход ищется при первом вызове функции команды или чтении `address`,** а не при запуске скрипта. Порядок в функции
  тот же, что у команды ([ADR-0006](0006-packages-and-the-entry-point.md)): тип параметров (`script_failed`), затем
  грамматика флагов CLI, например `limit` не меньше 1 (`bad_usage`), затем вход, затем SDK.
- **`fields` функции — всё выражение.** Пустое и начинающееся с `+` дают `script_failed`: это поля по умолчанию,
  которых у функции нет. `+` в `--fields` встроенной команды раскрывает её скрипт, склеивая свои поля по умолчанию
  с добавленными через запятую: SDK сливает поле, названное дважды.
- **Ошибка функции — объект только для чтения с прототипом `Error`.** `wrote` — код возврата этой ошибки был бы `2`.
- **`address` — адрес входа в написании [ADR-0008](0008-a-login-is-an-address-and-a-token.md) с замаскированным
  паролем,** потому что скрипт строит из него ссылки в свой вывод.
- **Модули исполняются в строгом режиме,** поэтому запись в ответ бросает `TypeError`, и непойманная становится
  `script_failed`.
- **Скрипт не добавляет кодов,** потому что агент, который читает `code`, знает все значения заранее. Код не из
  словаря [ADR-0005](0005-an-error-is-a-document.md) в `fail` и `warn` даёт `script_failed`, и сам `script_failed`
  тоже: его даёт только ytrack. Детали `fail` и `warn` не содержат `code` и `message`: они у ошибки уже есть.

## Ответ

- **Функция отвечает документом своей команды, и значения в нём помнят свой узел.** Отображение и список — объект и
  массив только для чтения в порядке узла. Число — `number`, если double представляет его точно, иначе `BigInt`.
  Отсутствующий ключ — `undefined`.
- **Значение из узла печатается как этот узел,** и когда его вернули из `run`, и когда вложили в возвращённое.
- **Значение, построенное скриптом, переводится по типу.** Строка с переводом строки становится многострочным
  текстом. Обычный объект становится отображением в порядке ключей, ключ со значением `undefined` опускается. Ключ
  не по грамматике собственных имён ([ADR-0003](0003-output-is-one-yaml-document.md)) закавычивается. Функция,
  символ, `NaN`, байты и `Date` дают `script_failed`.

## Реализовано

В `v1` пока только `project.show`, `project.list`, `fail`, `warn` и `address`. `fs`, `http`, декларации `v1.d.ts`, корпус
версии и предупреждение устаревшей версии приходят следующими шагами, как и функции записи, на которых проверяется
код `2` после записи.

## Кроме функций команд

- **`fs`:** `read`, `readText`, `write` и `mkdir` с путём по правилам [ADR-0006](0006-packages-and-the-entry-point.md).
  Место записи не ограничено. Недоступный путь даёт `bad_usage`.
- **`http.get(url, {timeout, maxBytes, follow})`** с обязательными параметрами, не дальше 10 редиректов, только
  `http` и `https`. **Статус вне `2xx` — ответ, а не ошибка.** Сбой транспорта, таймаут и тело длиннее `maxBytes`
  дают `upstream_failed`.
- **Токен инстанса в `http` не уходит никогда.** Куки и прокси из окружения не используются, запрос не повторяется.

## Версии

- **Версия — целое число в пути `require("ytrack/v1")`,** не связанное с календарной версией релиза
  ([ADR-0009](0009-completion-version-and-release.md)). Каждый модуль, в том числе библиотечный, подключает свою.
- **Старая версия — адаптер поверх текущей.** Реализация функции одна.
- **Поддерживаются текущая и предыдущая версии.** Версия снимается, когда вышла версия через одну и со следующей
  прошло 6 месяцев. Вызов на устаревшей версии выдаёт предупреждение `script_failed` с датой снятия и версией, на которую переходить;
  на снятой — ошибка.
- **Ломает версию:** убрать или переименовать функцию, параметр, собственный ключ `ytrack` в ответе или код;
  сменить тип или смысл любого из них; изменить правило кодов возврата. Новое необязательное не ломает.
- **Ответ сервера на `fields=` меняется с обновлением инстанса и версию не ломает.**
- **У каждой поддерживаемой версии есть корпус скриптов через `Run`,** который хотя бы раз использует каждую функцию
  и каждый собственный ключ версии.
- **Декларации `v<N>.d.ts` сверяются юнит-тестом `internal/script`**, потому что отставание деклараций через `Run`
  не видно. Остальные тесты движка раскладываются по слоям [ADR-0006](0006-packages-and-the-entry-point.md).

## Отвергнуто

- **Параметры в форме, удобной для JS** (`ownedBy`). Вторая грамматика рядом с CLI.
- **Значения по умолчанию CLI в API.** Правка полей по умолчанию ломала бы скрипты.
- **Ответ простыми JS-значениями.** Теряются многострочный текст, порядок ключей и признак ключей.
- **Версия в объявлении** и **диапазон релизов.** Расходится с `require` библиотечного модуля или умеет только давать ошибку.
- **Все версии навсегда** и **только срок.** Копятся адаптеры или живут три-четыре версии.
- **Тестовый режим для скриптов.** Хватает `YTRACK_URL` на свой сервер.
