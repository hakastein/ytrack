# Отсутствующее поле проверяется по типу, который назвал сервер

Под `200` сервер молча опускает и опечатку, и имя, которого нет у типа объекта. Здесь решено, когда отсутствующий
ключ даёт `unknown_name`, когда `upstream_invalid` ([ADR-0005](0005-an-error-is-a-document.md)), а когда ошибки нет.

## Решение

- **Отсутствующий ключ K проверяется по каталогу схем, по `$type` T, который сервер назвал у объекта:**

  | Случай | Результат |
  |---|---|
  | T из набора схем узла и объявляет K (сам или через предка) | `upstream_invalid` |
  | T из набора и не объявляет K, а другая схема набора объявляет | не ошибка, K опускается в узле этого объекта |
  | T не из набора (нет в каталоге, не назван, чужой узлу), а K объявлен в наборе | `upstream_invalid` |
  | K не объявляет ни одна схема набора | `unknown_name`; если имя запросил сам ytrack — `upstream_invalid` |

- **Имена проверяются после обхода всего ответа.** Если в ответе есть оба кода, ошибка — `upstream_invalid`, потому что
  исправленное имя не вернёт поле, которого сервер не прислал. Каждое поле называется один раз, в порядке обхода.
- **Полученное поле, которого нет в спецификации, не ошибка**, потому что спецификация отстаёт от сервера. В `nearest`
  такие имена не предлагаются.
- **Узел запроса** — корень ответа или поле, запрошенное у значений узла выше. Элементы списка относятся к узлу
  списка. **Набор схем** узла — схемы, которыми может быть объект в этом узле:
  - в корне — схема ответа операции с потомками, её называет команда;
  - ниже — схемы, которые набор выше объявляет у поля, с потомками;
  - если схема выше объявляет у поля скаляр или объект без схемы либо не объявляет поле вовсе — все схемы каждой
    иерархии, названной сервером в этом узле. Иерархия — схема без предка со всеми потомками;
  - к узлу можно дописать схемы сверх объявленных (`added` и `removed` активности получают `BundleElement`).
- **Подвыборка у скаляра проверяется как имена у объекта без типа.** Если набор выше объявляет поле скаляром или
  объектом без схемы (как `value` кастом-поля), скаляр печатается целиком. Ошибку тогда даёт только имя, которого
  не объявляет ни одна схема узла.
- **Имена под `customFields` сверяются с каталогом кастом-полей инстанса**, потому что это не свойства схем
  ([ADR-0004](0004-the-generator-owns-the-operation-surface.md)). Каталог берётся у инстанса, а не у проекта, потому
  что токену без роли в проекте поля проекта приходят пустыми. Он читается один раз за вызов и только если вызывающий
  назвал хотя бы одно имя. Имена из полей по умолчанию не сверяются. Каталог целиком читает и участник проекта без
  прав администратора.
  - Совпадение ищется как у сервера: без учёта регистра, по `name`, а при пустом `name` — по `localizedName`.
    Канонический `name` уходит в запрос и печатается ключом. Два имени одного поля дают один ключ на месте первого.
  - Нет совпадений — `unknown_name` под `unknown` с `nearest`. Несколько — `unknown_name` под `ambiguous` с
    `candidates`. `403` на каталоге — `denied`.
- **Имя `field` у активности несёт метку «ytrack читает по своему правилу»**, потому что сервер присылает там
  подтипы, которых нет в спецификации. Обход под него не спускается, содержимое проверяет правило печати. Имя
  вызывающего под `field` и под `category` — `bad_usage` до запроса.
- **Состав ошибки.** `unknown_name` несёт `request`, `fields` (отправленный `fields=`) и `unknown: [{field, nearest}]`.
  `upstream_invalid` несёт `missing: [{field, type}]`, где `type` — названный `$type` или `null`. Поле записано
  синтаксисом `fields=`. `nearest` — до пяти имён набора не дальше двух правок без учёта регистра, ближние первыми,
  затем по алфавиту. Если таких нет, это все имена набора.
- **Поле, скрытое правами, — тоже `upstream_invalid`**, и сообщение называет права возможной причиной. Поля по умолчанию
  не включают полей, которые могут скрыть права: так, участнику сервер не присылает `archived` у `Project`, и в полях
  по умолчанию `project show` его нет.
- **Каталог схем генерируется** `scripts/catalogue.go` из `api/openapi.json` в `internal/youtrack/catalogue.gen.go`
  (`make generate`) и руками не правится. `make ytapi` сверяет его с деревом байт в байт. Схема в нём записана под
  своим `$type`, с предком и видом каждого свойства. Там же помечены скаляры времени и многострочного текста
  ([ADR-0003](0003-output-is-one-yaml-document.md)). Генератор падает на любой незнакомой форме спецификации.

## Отвергнуто

- **Отсутствие ключа — всегда ошибка.** Ложные ошибки на `value(name,login)` и `bundle`.
- **Отсутствующий ключ просто опускается.** Опечатка выйдет с кодом 0.
- **Набор схем из присланных типов.** Результат зависел бы от данных.
- **`embedded-spec` от `oapi-codegen` или модели `internal/ytapi`.** В них нет подтипов.
- **Подтипы в overlay или рукописный список имён.** Вторая копия спецификации.
