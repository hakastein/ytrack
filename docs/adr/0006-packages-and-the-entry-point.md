# Пакет заводится ради второго импортёра, процесс виден только через `Run`, а SDK ytrack не тестирует

Здесь решено, как код раскладывается по пакетам, через какую точку входа наблюдается процесс и на каком слое
проверяется какое поведение.

## Решение

- **Пакет заводится, только если импортёру нужна часть без целого или у части своя причина меняться.** Иначе это
  файл, потому что граница пакета заставляет экспортировать то, что должно быть внутри.
  ```
  cmd/ytrack             процесс: вызов, сигналы, штамп бинарника, os.Exit
  internal/cli           cobra, Run, вход, грамматика флагов, вызов SDK, команды на Go
  internal/script        движок скриптов команд, объявление, корни, API скриптов
  internal/render        Renderer и YAML документа youtrack.Node
  internal/diag          Fault, перевод ошибки SDK, поток stderr
  ```
- **Всё знание о YouTrack — SDK [`github.com/hakastein/go-youtrack`](https://github.com/hakastein/go-youtrack)**
  (пакет `youtrack`): клиент с сервисами по сущностям, документ `*youtrack.Node`, выражение полей и проверка ответа,
  кастом-поля, запись, страницы, ошибка с кодом, транспорт, кэш метаданных и фейковый сервер `fake`
  ([ADR-0001 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0001-operations-are-methods-of-services.md)).
  Он нужен и kraken, и TMS. Правка SDK — его релиз, а ytrack поднимает версию в `go.mod`.
- **ytrack зовёт сервисы клиента напрямую** (`c.Issues.Show`, `c.Tags.Add`, `c.Users.Me`) и не видит ни
  сгенерированного клиента `ytapi`, ни `Client.API()`. Клиент строится на вызов:
  `youtrack.NewClient(адрес, токен, youtrack.WithMetadataCache(каталог))`.
- **Импорты:** `cmd/ytrack → cli → script → youtrack, render, diag`; `cli → youtrack, render, diag`;
  `diag → render, youtrack`; `render → youtrack`. `fake` SDK импортируют только тесты `cli`.
- **CLI держит только грамматику флагов** (`internal/cli/write.go`): `Name=value` у `--field` и `--attribute`, слова
  `--clear`, период `PT1H30M`, `--comments`, `--limit`, отказ на пустом флаге, который SDK прочёл бы как «не дан»
  ([ADR-0002](0002-field-metadata-is-a-struct.md), [ADR-0010](0010-a-list-page.md)). Остальные аргументы уходят в
  SDK как написаны.
- **Ограничителя частоты нет, пока запросы идут по одному.**
- **Ошибка — первая проваленная проверка, и до вызова SDK сеть не используется.** Порядок: разбор cobra, грамматика
  флагов CLI, вход — адрес, его форма, токен, его форма ([ADR-0008](0008-a-login-is-an-address-and-a-token.md)), —
  затем вызов SDK, который до сети проверяет свои аргументы: вид id, выражение полей, диапазон страницы. Поэтому без
  адреса и токена ошибка аргумента, которую находит SDK, уступает `denied` «no login was found», а отказ грамматики
  флагов приходит раньше входа.
- **Каждая функция, переданная cobra, возвращает `*diag.Fault`, и код возврата решает он.** Ошибка Go, дошедшая до
  `Run` не `Fault`ом, становится `bad_usage`.

## Точка входа `Run`

```go
func Run(ctx context.Context, argv, env []string, build *debug.BuildInfo, stdin *os.File,
	stdout, stderr io.Writer) int
```

- **Процесс трогает только `cmd/ytrack` и передаёт его части `Run` как есть.** `Run` — единственный экспорт `cli`.
  Адрес, токен и `HOME` берутся из `env`, каталог вызова — рабочий каталог процесса
  ([ADR-0008](0008-a-login-is-an-address-and-a-token.md)).
- **`os.Interrupt` и `SIGTERM` отменяют контекст, второй сигнал убивает процесс (130).** Ниже `Run` о сигнале не
  знают, и отменённая запись — `write_uncertain`.
- **Путь из вызова и путь `fs` скрипта передаются как написаны**, относительный — от рабочего каталога процесса.
  Существующий путь не к обычному файлу — `bad_usage`, потому что именованный канал ждёт писателя вечно. `-` — это
  файл с таким именем. Сам `ytrack` в проект не пишет ([ADR-0011](0011-a-command-is-a-script.md)).
- **Штамп бинарника ниже `Run` не читают**, потому что у тестового бинарника его нет
  ([ADR-0009](0009-completion-version-and-release.md)).
- **У `stdin` спрашивает только `auth login` и только, терминал ли это.** `/dev/tty` не открывается, потому что у
  агента терминала нет.
- **Команду `help` заменяет скрытая `no-help`**, потому что cobra перечисляет в справке и скрытую `help`.
- **Состояния на уровне пакета нет**, дерево cobra и рантайм скриптов строятся на каждый вызов.

## Тесты

**ytrack не тестирует SDK:** SDK покрыт своими тестами
([ADR-0005 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0005-tests-are-contracts-against-the-fake.md)).
Тест ytrack проверяет только то, что принадлежит ytrack, и падает, только когда ломается поведение, названное в его
имени.

### Слои

- **Слоёв два: юнит под `Run` и интеграционный через `Run`. Контрактного слоя нет.** Тест против дев-инстанса
  проверяет сам YouTrack и краснеет со сменой его версии, когда ytrack ничего не нарушил. Факт о сервере, на котором
  стоит решение, записан в ADR. Измерен он на YouTrack 2026.1.13757 — сборке дев-инстанса (`dev/`), — если рядом не
  названа другая версия. Дев-инстанс остаётся для `make openapi` SDK, ручных проверок и новых измерений.
- **Юнит-слой проверяет пакет через его экспорт:**
  - `internal/render` — стиль скаляров и многострочного текста, ключи, запись списка в одну строку, отказ до первого
    байта;
  - `internal/diag` — перевод `*youtrack.Error` в `Fault`, код возврата, поток stderr, в том числе запасной путь
    `render_error` ([ADR-0005](0005-an-error-is-a-document.md)) через `NewStream` с `Renderer`, который возвращает
    ошибку;
  - `internal/script` — сверка `v<N>.d.ts` с движком ([ADR-0012](0012-the-script-api.md)).
- **Ради теста экспорт не заводится.**
- **Интеграционный слой через `Run` проверяет только принадлежащее CLI:** грамматику флагов и её отказ до сети (код 1,
  запросов 0); вход ([ADR-0008](0008-a-login-is-an-address-and-a-token.md)); склейку argv в вызов SDK — один успешный
  путь на команду; документ ошибки и код возврата (1; 2 для `write_uncertain` и `AfterWrite`); рендер; протокол
  автодополнения; `--version`. Этот слой доказывает, что перенос команды в скрипт
  ([ADR-0011](0011-a-command-is-a-script.md)) сохранил поведение.
- **Знание SDK тесты ytrack не проверяют:** какой `fields=` он шлёт, тела записи, проверки ответа, детали ошибок,
  подсчёт страниц, форму id.
- **Каждую гарантию ADR ytrack, у которой есть код, держит хотя бы один тест**, и мутация, которая её снимает, роняет
  его.

### Что тест сверяет

- **Чужой код и YouTrack не проверяются:** SDK, cobra и pflag (неизвестный флаг, арность из `cobra.Args`, справка,
  `--`, значение с дефисом), `encoding/json`, `net/url`, а также поиск, воркфлоу, маршруты и права самого сервера.
- **Проза не сверяется — ни своя (`message`, подсказка, справка), ни SDK, ни сервера**, потому что правка
  формулировки не меняет поведения. `NotEmpty` на прозе допустим. Код ошибки сверяется значением, потому что по нему
  ветвится агент.
- **Ассерт стоит на значение**, а не на тип, длину или непустоту.
- **Фейковый сервер отвечает тесту, не глядя на `fields=`**, поэтому правка полей по умолчанию у команды тестов не
  роняет.
- **Фикстура названа по проверяемому свойству**, а не взята с дев-инстанса.
- **Таблица ошибок сверяет, каким правилом отвергнут кейс**, — код и то, отвергнут ли он до сети, — чтобы кейс,
  отвергнутый не тем правилом, не оставался зелёным.
- **В теле теста нет логики.** Таблица — одна форма кейсов, а кейсу со своей веткой нужен свой тест.
- **Тест — во внешнем пакете `_test`, на testify и таблицах.** Тестовых швов в проде нет.

### Фейковый сервер

- **Фейковый сервер — пакет `fake` SDK:** один сервер на тестовый пакет, свой префикс пути на тест, журнал запросов
  через `require`
  ([ADR-0005 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0005-tests-are-contracts-against-the-fake.md)).
- **Окружение `Run` к фейковому серверу — `YTRACK_URL` и `YTRACK_TOKEN` — собирает хелпер тестов ytrack**, потому что
  переменные входа принадлежат ytrack, а не SDK.
- **Отказ до сети проверяется против `fake.ServeNothing`**, который роняет тест на любом запросе.
- **Скрипты команд тест кладёт в корень пользователя под временным `HOME`.** Корень проекта ищется от рабочего
  каталога процесса, поэтому тест корня проекта последовательный и делает `t.Chdir`.
- **Свой сервер поднимает только тест, которому общий не годится:** перестать слушать между двумя запросами
  (`fake.ServeAlone`).
