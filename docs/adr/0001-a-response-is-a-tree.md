# Ответ — дерево, а не сгенерированные структуры

Команда печатает документ `*youtrack.Node`, который SDK строит под выражением полей вызывающего. Как строится
документ и когда отсутствующее имя — ошибка, решено в
[ADR-0006 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0006-a-document-is-a-tree-under-the-callers-fields.md).
Здесь — что из этого видит вызывающий ytrack.

## Решение

- **`--fields` передаётся SDK как написан**, без своей грамматики: пусто — поля по умолчанию команды, `+x` — они и
  `x`.
- **Одно неверное имя проваливает всю команду, stdout остаётся пустым**, потому что неполную запись пайп принял бы за
  полную.
- **Команда записи печатает документ записанного**, потому что воркфлоу инстанса может поменять другое поле: запись
  закрывающего `State` ставит `resolved`, а связь «дубликат» ставит целевой задаче `State: Duplicate`, и ответ на
  запись это уже несёт.
- **Доступ к тегу задают три флага `tag create`:** `--visible-for`, `--taggable-by` и `--updateable-by`, по одному
  на набор доступа. Вешать тег даёт только `--taggable-by`.

## Активности

- **Активности есть только у задачи:** `activity list <задача>`.
- **Без `--category` уходят все категории.** `--category` дополняется из словаря категорий
  ([ADR-0009](0009-completion-version-and-release.md)).

## Отвергнуто

- **Отдельная команда для коммитов.** Своей подкоманды у коммита нет: это активность категории `VcsChangeCategory`.
- **Активности задач из `--query`.** Какие задачи менялись, отвечает язык поиска.
