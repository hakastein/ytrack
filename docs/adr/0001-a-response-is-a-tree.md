# Ответ — дерево, а не сгенерированные структуры

Сервер присылает только поля из `fields=`, поэтому по ответу не понять, пустое поле или его не запрашивали.
Сгенерированные структуры не умеют отправить `null` и различить «не запрошено» и «пусто».

## Решение

- **Ответ и тело запроса — деревья.** Отсутствующий ключ в теле — третье состояние рядом с текстом и явным пустым
  значением, и такую часть сервер не меняет.
- **`fields=` выбирает вызывающий.** Выражения «запросить всё» нет, потому что схема рекурсивна.
- **Поля по умолчанию — только те, которые видит любой читатель**, иначе исход зависел бы от прав.
- **Синтаксис проверяется до запроса, имена — после.** Проверка имён не спускается ниже `null` или `[]`.
- **Одно неверное имя проваливает всю команду, stdout остаётся пустым**, потому что неполную запись пайп принял бы за
  полную. Ошибка называет имя, которого нет в ответе, ближайшие имена его схемы и отправленный `fields=`.
- **Команда записи печатает результат**, потому что воркфлоу инстанса может поменять другое поле.
- **Пометка `readOnly` в спецификации не мешает писать поле.** Так ложно помечены `$type` и три набора доступа к тегу.
  Флаги `tag create` пишут эти наборы, а не `visibleFor`.

## Значения журнала

- **Владелец журнала — только задача.**
- **`added` и `removed` — всегда список**, чтобы все записи читались одинаково. `null` печатается как `[]`, одиночное
  значение — как список из одного элемента.
- **Скалярный элемент печатается скаляром, объект — деревом по запрошенным именам.** Имя, которого не объявляет
  `$type` элемента, у него опускается.
- **Поля по умолчанию — `added(id,idReadable,login,name,urls)` и то же под `removed`.**
- **`target` не запрашивается и не печатается**, потому что задачу вызывающий назвал сам.
- **`category` — идентификатор YouTrack, `field` — имя кастом-поля в проекте или непереведённая фраза связи.**
  Вложенное имя под любым из них — `bad_usage`.
- **Под `added` и `removed` у любого журнала один набор схем**, чтобы имя проверялось одинаково при любом составе
  журнала. Это схемы иерархии `ActivityItem` для этого узла запроса и `BundleElement`, которого спецификация там не
  объявляет.
- **Имя вне набора схем — `unknown_name` до запроса**, потому что `removed` почти всегда приходит `[]`.
- **Голое значение кастом-поля читается по типу поля.** Значение другой формы — `upstream_invalid`.
- **`VcsChangeCategory` входит в набор категорий по умолчанию.** `--category` дополняется из словаря категорий
  ([ADR-0009](0009-completion-version-and-release.md)).

## Отвергнуто

- **Тела с тремя состояниями по всей спецификации.** `$type` и `value` остались бы нерешёнными.
- **Одно имя на значение журнала по категории.** Коммиту нужны и ссылка, и сообщение.
- **Отдельная сущность для коммитов.** Своего глагола у коммита нет.
- **Журнал задач выборки (`--query`).** Какие задачи менялись, отвечает язык поиска.

## Следствия

- От сгенерированного клиента остаётся поверхность операций, но не тела
  ([ADR-0004](0004-the-generator-owns-the-operation-surface.md), [ADR-0006](0006-packages-and-the-entry-point.md)).
- Компилятор не проверяет тела. Опечатку в имени поля ловят контрактные тесты против живого инстанса.
- Своё правило чтения ([ADR-0007](0007-missing-fields-are-checked-by-server-type.md)) осталось только у `field` журнала.
