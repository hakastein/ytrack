# Команда — скрипт, и ytrack не поставляет процессов

Агент повторяет одни и те же процедуры из нескольких вызовов ytrack. Процедура у каждой группы людей своя, поэтому
ytrack даёт способ записать её командой, а не саму процедуру.

## Решение

- **Каждая команда — скрипт команды,** который выполняется через API скриптов ([ADR-0012](0012-the-script-api.md)).
  Встроенные команды — скрипты, вшитые в бинарник, и встроенному недоступно ничего, что недоступно скрипту проекта.
  На Go остаются `auth`, `completion`, протокол автодополнения и `--version`.
- **ytrack не поставляет процессов.** Ни встроенные команды, ни API не содержат агрегатов и знаний о чьём-либо
  процессе.
- **Язык — JavaScript на [goja](https://github.com/dop251/goja),** потому что в нём `undefined` и `null` разные
  ([ADR-0006 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0006-a-document-is-a-tree-under-the-callers-fields.md)).
  Модули — CommonJS: `require` и `exports`, потому что ES-модулей в goja
  нет.
- **Исполнение синхронное,** `Promise` нет. Движок — фреймворк cliche, и его правила исполнения, объявления, разбора
  вызова и источников записаны в [ADR-0001 cliche](https://github.com/hakastein/cliche/blob/main/docs/adr/0001-the-framework-is-mechanisms.md); здесь — что из них берёт ytrack и что решает сам. Своё ytrack держит в пакете
  `internal/script`: модуль `ytrack/v1`, тип `fields` и правило корней.
- **Инстанс — только через функции API, а кроме него — только файлы через `fs` и HTTP `GET` через `fetch`,** как в
  Node ([ADR-0012](0012-the-script-api.md)). Процессы скрипт не
  запускает, окружение не читает. Из входа ему доступен только `address`.
- **Встроенными скриптами владеет ytrack, скриптами проекта и пользователя — тот, кто их запускает.** Поэтому
  дефект встроенного скрипта — паника ytrack, а `script_failed` бывает только у чужого скрипта
  ([ADR-0005](0005-an-error-is-a-document.md)).
- **Скрипту доверяют так же, как репозиторию, в котором он лежит,** поэтому песочницы нет. Сам `ytrack` в проект
  не пишет.
- **Команды переносились вместе с подкомандами, первая — `project`.** Команда перенесена, когда тесты всех её
  подкоманд через `Run` проходят без правок. Перенесены все, кроме `auth` и `completion`.

## Объявление

- **Объявление команды — чистый литерал `exports.definition`,** который cliche читает, не выполняя модуль, потому
  что справке и каждому TAB нужны объявления всех скриптов. Саму команду выполняет функция `exports.command`.
- **Вызов разбирает объявление, а грамматику CLI — скрипт.** Значения, у которых есть тип (`Name=value`,
  `PT1H30M`, выражение полей), разбирает cliche по объявлению; остальную грамматику своей команды — какие слова
  берёт `--clear`, что значит `--comments all` — скрипт на JS, и ошибки даёт через `fail("bad_usage", …)`. В API
  скриптов грамматики CLI нет ([ADR-0012](0012-the-script-api.md)).
- **Вызов разбирает cliche.** Его отказ — неизвестный флаг, значение вне `choices`, лишний аргумент — ytrack
  печатает `bad_usage` до выполнения скрипта.
- **Форма литерала — форма cliche,** и ytrack берёт из неё часть. `long` пишется отдельно и не выводится из `short`
  ([ADR-0009](0009-completion-version-and-release.md)). Форму ответа скрипт задаёт сам, объявление её не описывает.
- **Аргумент** — `string`, `path` или `duration`, каждый дан ровно один раз: групп, `optional` и `multiple`, как и
  аргументов `int` и `pair`, у ytrack нет, и объявление с ними — сломанный путь.
- **Флаг** — одного из типов ниже; флага `path` у ytrack нет. Тип задаёт, что получит скрипт, и правило одно для
  любого флага любого скрипта, какое бы имя у него ни было:

| `type` | что получает `command` |
|---|---|
| `string` | строку как есть; при `choices` — одну из них |
| `int` | целое в 32 бита, как число API; более широкое — `bad_usage` до запуска |
| `bool` | `true` или `false` |
| `fields` | выражение полей: `default`, если флаг не дан или пуст; `+expr` — `default`, запятая и `expr` |
| `pair` | `{ Name: "value" }` из `Name=value`; значение без `=` или без имени — `bad_usage` до запуска |
| `duration` | целые минуты из периода ISO 8601 часов и минут, `PT1H30M` — `90`; другой период — `bad_usage` до запуска |

- **`multiple`, `choices` и `default` — по правилам cliche:** `pair` с `multiple` собирает пары в один объект, а имя,
  данное несколько раз, — в массив его значений: `--field "Fix versions=1.0" --field "Fix versions=1.1"` — это
  `{ "Fix versions": ["1.0", "1.1"] }`.
- **`fields` — тип приложения ytrack:** `default` у него обязателен, потому что `+` к нему добавляет, а `usage` задаёт
  ytrack: это правило `+`, одинаковое у всех команд. Значения по умолчанию есть у команды, а не у функций API
  ([ADR-0012](0012-the-script-api.md)): скрипт передаёт функции готовые значения.
- **`+` раскрывается склейкой, потому что SDK сливает поле, названное дважды.** Своих полей по умолчанию у SDK нет
  (v0.5.0): его выражение — `fields=` REST API как есть, и `+` к полям по умолчанию — правило ytrack, одинаковое для
  всех команд.
- **`exports.command` получает аргументы в объявленном порядке, затем объект флагов с именами, как после `--`.**
  `ytrack project show DEV --fields name` — это `command("DEV", { fields: "name" })`, и скрипт сам решает, как это
  становится вызовом `projects.show({ project: "DEV", fields: "name" })`. Объект флагов передаётся всегда, даже
  пустой. `command` возвращает объект: он и печатается.
- Объявление, которое cliche не читает или которое берёт больше, чем ytrack, делает путь сломанным.
- Модуль с нечитаемым объявлением в дерево команд не попадает. `--help` о нём предупреждает, вызов по имени даёт
  `script_failed` ([ADR-0005](0005-an-error-is-a-document.md)).

## Корни и имена

- **Скрипты берутся из корней cliche по умолчанию для имени `ytrack`:** ближайшего `.ytrack/scripts` над каталогом
  вызова, по которому выбирается запись входа ([ADR-0008](0008-a-login-is-an-address-and-a-token.md)), и
  `~/.ytrack/scripts` под `HOME` из окружения `Run`, а не процесса. Путь команды, библиотечный модуль, `require`,
  сломанные пути и чтение каталогов — по [ADR-0001 cliche](https://github.com/hakastein/cliche/blob/main/docs/adr/0001-the-framework-is-mechanisms.md).
- **Первое слово пути команды принадлежит одному корню.** Если оно есть у встроенной команды, работают только
  встроенные; иначе, если оно есть в корне проекта, — только команды проекта; иначе — команды пользователя. Поэтому
  нельзя ни заменить `issue show`, ни добавить `issue close`. О файле, скрытом встроенной командой, предупреждает
  каждый вызов с тем же первым словом.
- **Сломанный путь в дерево команд не попадает:** `--help` о нём предупреждает, вызов даёт `script_failed`.
- **Первое слово занимает только корень, у которого под ним есть команда или сломанный путь:** библиотечный модуль
  слова не занимает.
- **Корень или каталог, который не читается, — предупреждение `script_failed` в `--help`,** а не пропуск. Если
  рабочий каталог не читается, например удалён, корня проекта нет.
- **Предупреждение `--help`** — о путях не ниже команды, справку которой печатают; `--help` самого `ytrack`
  называет ещё и скрытые встроенными командами файлы.
- **Скрипт не вызывает другие команды и не подключает модули чужого корня.** Складывать процедуры из разных
  корней — дело вызывающего.
- **`--help` показывает скрипты отдельным блоком, у каждого — корень, откуда он взят.** Автодополнение знает их
  имена, флаги и `choices`.

## Отвергнуто

- **Пайпы и список shell-команд в файле проекта.** Нет ветвлений и сборки текста.
- **Внешние программы `ytrack-<имя>`.** Процесс на шаг, контракт держит каждая сама.
- **Встроенные команды на Go и API уровня CLI.** API проверял бы только пользователь, а скрипт только передавал бы
  флаги дальше.
- **Lua и Starlark.** В Lua один `nil`, в Starlark нет регулярок.
- **sobek с ES-модулями.** Это форк goja, и модули в нём экспериментальные.
- **Исполняемое объявление и манифест отдельным файлом.** Код на каждый TAB или два файла.
- **`ytrack run`.** Скрипт сам является командой.
- **Объявленный формат вывода и пример ответа.** Форма ответа — это выражение полей, которое агент видит в `--help`,
  и одна его структура не описывает. Пример отстаёт от ответа, а спецификация повторяет запрос.
