# Команда — скрипт, и ytrack не поставляет процессов

Агент повторяет одни и те же процедуры из нескольких вызовов ytrack. Процедура у каждой группы людей своя, поэтому
ytrack даёт способ записать её командой, а не саму процедуру.

## Решение

- **Каждая команда — скрипт команды,** который выполняется через API скриптов ([ADR-0012](0012-the-script-api.md)).
  Встроенные команды — скрипты, вшитые в бинарник, и встроенному недоступно ничего, что недоступно скрипту проекта.
  На Go остаются `auth`, `completion`, протокол автодополнения и `--version`.
- **ytrack не поставляет процессов.** Ни встроенные команды, ни API не содержат агрегатов и знаний о чьём-либо
  процессе.
- **Язык — JavaScript на [goja](https://github.com/dop251/goja),** потому что в нём `undefined` и `null` разные
  ([ADR-0006 SDK](https://github.com/hakastein/go-youtrack/blob/main/docs/adr/0006-a-document-is-a-tree-under-the-callers-fields.md)).
  Модули — CommonJS: `require` и `exports`, потому что ES-модулей в goja
  нет.
- **Исполнение синхронное,** `Promise` нет. Движок — пакет `internal/script`, среда создаётся на каждый вызов `Run`.
- **Инстанс — только через функции команд, а кроме него — только `fs` и HTTP `GET`.** Процессы скрипт не
  запускает, окружение не читает. Из входа ему доступен только `address`.
- **Встроенными скриптами владеет ytrack, скриптами проекта и пользователя — тот, кто их запускает.** Поэтому
  дефект встроенного скрипта — паника ytrack, а `script_failed` бывает только у чужого скрипта
  ([ADR-0005](0005-an-error-is-a-document.md)).
- **Скрипту доверяют так же, как репозиторию, в котором он лежит,** поэтому песочницы нет. Сам `ytrack` в проект
  не пишет.
- **Команды переносятся вместе с подкомандами, первая — `project`.** Команда перенесена, когда тесты всех её
  подкоманд через `Run` проходят без правок. Перенесена `project`; остальные пока написаны на Go и живут рядом.

## Объявление

- **Объявление команды — чистый литерал `exports.command`** без имён, вызовов и вычислений. Движок читает его
  парсером, не выполняя модуль, потому что справке и каждому TAB нужны объявления всех скриптов.
- **Вызов разбирает движок.** Неизвестный флаг, значение вне `choices` и лишний аргумент дают `bad_usage` до
  выполнения скрипта.
- **Форма литерала.** `short` и `long` обязательны: `long` пишется отдельно и не выводится из `short`
  ([ADR-0009](0009-completion-version-and-release.md)). `args` и `flags` — массивы одной формы: каждый элемент —
  объект с `name`, `type` и `usage`. `usage` — строка справки и подсказки TAB; слово в обратных кавычках становится
  именем значения, как у pflag. `example` — ответ команды, он печатается после `long` через `render.YAML`.
  Неизвестный ключ на любом уровне делает объявление нечитаемым.
- **Аргумент** — `string` или `path`; `path` дополняется как имя файла.
- **Флаг** берёт ещё `choices` и `default`. Тип задаёт, что получит скрипт, и правило одно для любого флага любого
  скрипта, какое бы имя у него ни было:

| `type` | что получает `run` |
|---|---|
| `string` | строку как есть; при `choices` — одну из них |
| `strings` | массив строк; флаг повторяется, при `choices` каждая — одна из них |
| `int` | целое в 32 бита, как параметр функции команды; более широкое — `bad_usage` до запуска |
| `bool` | `true` или `false` |
| `fields` | выражение полей: `default`, если флаг не дан или пуст; `+expr` — `default`, запятая и `expr` |

- **`default` тоже одно для всех типов:** флаг с ним есть у `run` всегда, флаг без него — только когда вызов его дал.
  `default` того же типа, что флаг, и из его `choices`. У `fields` `default` обязателен, потому что `+` к нему
  добавляет, а `usage` задаёт ytrack: это правило `+`, одинаковое у всех команд. Значения по умолчанию есть у
  команды, а не у функций API ([ADR-0012](0012-the-script-api.md)): скрипт передаёт функции готовые значения.
- **`+` раскрывается склейкой, потому что SDK сливает поле, названное дважды.** У задач SDK отличает поля, которые
  назвал вызывающий, от полей по умолчанию, и названное кастом-поле печатает даже пустым, поэтому для группы `issue`
  `+` придётся раскрывать в SDK.
- **Имя аргумента, флага и слово пути** — строчные буквы, цифры, `-` и `_`, не с `-` и не с `_`. Имена аргументов не
  повторяются, имена флагов — тоже и не `help`.
- **Команду выполняет `exports.run`, и вызывается он как функция команды:** аргументы в объявленном порядке, затем
  объект флагов с именами, как после `--`. `ytrack project show DEV --fields name` — это
  `run("DEV", { fields: "name" })` и `project.show("DEV", { fields: "name" })`. Объект флагов передаётся всегда, даже
  пустой. `run` возвращает объект: он и печатается.
- Модуль с нечитаемым объявлением в дерево команд не попадает. `--help` о нём предупреждает, вызов по имени даёт
  `script_failed` ([ADR-0005](0005-an-error-is-a-document.md)).

## Корни и имена

- **Скрипты берутся из двух корней:** ближайшего `.ytrack/scripts` над каталогом вызова, по которому выбирается запись входа
  ([ADR-0008](0008-a-login-is-an-address-and-a-token.md)), и `~/.ytrack/scripts` под `HOME` из окружения `Run`.
  Симлинки внутри корней разрешаются.
- **Путь файла в корне задаёт путь команды:** `docs/map.js` — это `ytrack docs map`. Файл без `command` —
  библиотечный модуль. `require` принимает только относительный путь внутри своего корня и `ytrack/v<N>`.
- **Первое слово пути команды принадлежит одному корню.** Если оно есть у встроенной команды, работают только
  встроенные; иначе, если оно есть в корне проекта, — только команды проекта; иначе — команды пользователя. Поэтому
  нельзя ни заменить `issue show`, ни добавить `issue close`. О файле, скрытом встроенной командой, предупреждает
  каждый вызов с тем же первым словом.
- **Путь — либо файл команды, либо каталог её подкоманд.** Если в корне есть и `x.js`, и каталог `x/`, ни то ни
  другое не попадает в дерево команд: `--help` о них предупреждает, вызов даёт `script_failed`. Библиотечный
  модуль `x.js` рядом с каталогом без команд конфликта не даёт.
- **Первое слово занимает только корень, у которого под ним есть команда или сломанный путь:** библиотечный модуль
  слова не занимает.
- **Каталог становится командой, если под ним есть команда.** Его `Short` — «Run the `<слово>` commands»: описать
  каталог нечем, кроме имени. Каталог, под которым только сломанные пути, скрыт.
- **Файл и каталог с точкой в начале имени не читаются.** Путь команды короче восьми слов: глубже каталог не
  читается, потому что симлинк на каталог выше иначе обходился бы вечно.
- **Если ближайший `.ytrack/scripts` над каталогом вызова — это `~/.ytrack/scripts`,** корня проекта нет: те же
  скрипты не становятся командами дважды. Если рабочий каталог не читается, например удалён, корня проекта тоже нет.
- **Корень или каталог, который не читается, — предупреждение `script_failed` в `--help`,** а не пропуск.
- **Предупреждение `--help`** — о путях не ниже команды, справку которой печатают; `--help` самого `ytrack`
  называет ещё и скрытые встроенными командами файлы.
- **Файл встроенного скрипта называется `builtin:<путь>`,** файл корня — абсолютным путём внутри корня, как он
  записан, без разрешения симлинков.
- **Скрипт не вызывает другие команды и не подключает модули чужого корня.** Складывать процедуры из разных
  корней — дело вызывающего.
- **`--help` показывает скрипты отдельным блоком, у каждого — корень, откуда он взят.** Автодополнение знает их
  имена, флаги и `choices`.

## Отвергнуто

- **Пайпы и список shell-команд в файле проекта.** Нет ветвлений и сборки текста.
- **Внешние программы `ytrack-<имя>`.** Процесс на шаг, контракт держит каждая сама.
- **Встроенные команды на Go и API уровня CLI.** API проверял бы только пользователь.
- **API ниже функций команд.** Сервисы SDK пришлось бы переписать на JS.
- **Lua и Starlark.** В Lua один `nil`, в Starlark нет регулярок.
- **sobek с ES-модулями.** Это форк goja, и модули в нём экспериментальные.
- **Исполняемое объявление и манифест отдельным файлом.** Код на каждый TAB или два файла.
- **`ytrack run`.** Скрипт сам является командой.
