# Метаданные кастом-поля — Go-структура, значение — дерево

Значение кастом-поля приходит под `fields=` вызывающего и остаётся деревом ([ADR-0001](0001-a-response-is-a-tree.md)).
Метаданные ytrack запрашивает своим выражением и получает целиком, поэтому дерево им не нужно.

## Решение

- **Метаданные поля — Go-структура из сравнимых членов**, чтобы второй запрос сверял её целиком.
- **Метаданные проекта берутся одним запросом к проекту** (или к задаче, под `project(…)`). Тип и кратность — из
  `field.fieldType`. Настройки кастом-полей инстанса и `/api/commands` не запрашиваются.
- **Пустой список кастом-полей проекта — `denied` с `project` и `permission`**, потому что токену без права на
  чтение проекта сервер отвечает `200` и пустым списком, а не `403`.
- **Таблица типов выписана вручную, по строке на пару `(valueType, isMultiValue)`**, потому что она нерегулярна.
  Строка задаёт бандл, ключ значения и `$type` тела записи. Таблица живёт в модуле youtrack
  ([ADR-0003 модуля](https://github.com/hakastein/youtrack/blob/main/docs/adr/0003-a-field-type-is-a-row-of-the-table.md)): ytrack берёт у `FieldType` класс тела записи,
  кодирование и чтение значения, правило сравнения и выражение бандла, а своей таблицы не держит.
- **`$type` в теле записи копируется, а не вычисляется.** Поле, которое стоит на задаче, пишется классом, который
  назвал сервер, а поле, которого нет, — классом из таблицы.
- **Ключ значения зависит от типа:**

  | valueType | ключ значения | как пишется |
  |---|---|---|
  | enum, state, version, build, ownedField, group | `name` | `name` |
  | user | `login` | `login` |
  | period | ISO-8601 из `minutes` | `{"minutes": N}` |
  | date | день ISO-8601 в UTC | полдень UTC этого дня в миллисекундах |
  | date and time | момент ISO-8601 в UTC ([ADR-0003](0003-output-is-one-yaml-document.md)) | миллисекунды |
  | integer, float, string | сам скаляр | скаляр |
  | text | `text`, печатается многострочным текстом | `{"text": …}` |

  Число `integer` и `float` ytrack печатает таким, как его прислал сервер, а не записью, которую даёт модуль. Значение,
  которое модуль не читает как ключ своего типа (дробь в `integer`), — `upstream_invalid`.

- **Бандл — `values` у enum, state, version, build и ownedField, `aggregatedUsers` у user.** У
  остальных типов источника нет. `bundle.values` пользовательского поля — не те, кого поле принимает, а группы.
  Пустой `aggregatedUsers` значит, что поле принимает любого пользователя.
- **Пользователь пишется только логином.** `me` сервер не читает как вызывающего, а пользователя вне
  `aggregatedUsers` отвергает — в обоих случаях `400`, то есть `rejected`.
- **Имена полей ytrack разрешает сам:** по `name`, затем по `localizedName` проекта, без учёта регистра. В тело уходит
  канонический `name`, потому что на любое другое имя сервер отвечает `500`.
- **Имена значений разрешает сервер.** Он исправляет регистр (`новая` — `Новая`, `ADMIN` — `admin`), поэтому
  проверка записи регистр не учитывает. Имя не из бандла он отвергает `400`.
- **Многозначное поле пишется целиком:** вызывающий перечисляет весь набор значений. Сервер заменяет им весь набор
  и возвращает значения не в порядке записи, поэтому проверка записи сравнивает их как набор.
- **Опустошение пишет `null` в однозначное поле и в описание, а в многозначное — `[]`.**
- **Обязательные поля проверяются до запроса при создании, и `missing_required` называет их все.** Поле, которое
  проект заполняет сам, и поле, скрытое условием, не требуются. Обновление проверяет только поля, которые опустошает.
- **Поле, скрытое условием, ytrack отвергает только при создании**, потому что тогда сервер молча его отбрасывает.
  При обновлении такую запись сервер отвергает сам, `400`. Условие он вычисляет по значениям той же записи: поле,
  открытое значением из того же тела, сохраняется, а если обязательно — требуется, поэтому и ytrack вычисляет
  условие по телу.
- **Запись читает метаданные с сервера, а не из кэша.**
- **Поля проекта печатаются по `ordinal`, при равенстве — в порядке ответа.** Сервер отдаёт их в порядке `id`
  привязки, а у полей, привязанных через REST, `ordinal` одинаковый — `0`.
- **Период печатается из `minutes` как `PT{H}H{M}M`**, потому что `P1D` сервера — рабочий день инстанса, 480 минут.
- **Период и длительность записи времени пишутся только как `{"minutes": N}`**, потому что одно `id` опустошает поле,
  а длительность записи времени с одним `id` сервер отвергает `400`.
- **На вход период принимается только как `PT…H…M`, короче `2^31` минут.** Ноль проверяет сервер.
- **Дата пишется полднем UTC**, потому что он приходится на один день во всех поясах от UTC−12 до UTC+11:59. Момент
  сервер относит ко дню в поясе профиля автора и хранит полночь UTC этого дня.
- **Запись времени без `--date` уходит без `date`**, и сервер пишет её на свой сегодняшний день. Обновление записи
  времени несёт только переданные ключи: остальные сервер не трогает, а `null` в `type`, `text` и в `value` атрибута
  их опустошает. Текст записи сервер хранит байт в байт, с CR и пробелами по краям.
- **Допустимые типы работ — набор проекта `plugins.timeTrackingSettings.workItemTypes`**, который ytrack читает с
  задачи. Имя не из набора — `unknown_name` до запроса. Тип отправляется только по `id`. Набор приходит и при
  выключенном учёте времени, поэтому `project show` печатает `enabled` рядом с ним.

## Кэш метаданных

- **Кэш держит модуль youtrack** (`WithMetadataCache`, [ADR-0003 модуля](https://github.com/hakastein/youtrack/blob/main/docs/adr/0003-a-field-type-is-a-row-of-the-table.md)). Каталог принадлежит паре
  адреса и токена, потому что права фильтруют и поля, и значения. Каталоги `0700`, файлы `0600`, токена в файлах нет.
  Кэш пишется сразу после ответа, чтобы вызов, кончившийся ошибкой, оставлял его тёплым. ytrack даёт модулю каталог
  `~/.ytrack/cache`, а без абсолютного `HOME` кэша нет.
- **Кэш читает и пишет только `field show`**, через `Metadata` модуля, поэтому его метаданные запрашиваются выражением
  модуля: `id,shortName,customFields(id,ordinal,canBeEmpty,field(name,localizedName,fieldType(valueType,isMultiValue)))`.
- **Кэш подтверждает, но не даёт ошибки.** Всякое расхождение с сервером — промах, после которого метаданные читаются
  заново `ReadMetadata`. `denied`, `rejected`, сбой сети, 5xx и ошибка грамматики `--fields` промахом не считаются.
- **Ответ на метаданные `field show` проверяет модуль по своей форме, а не каталог схем
  ([ADR-0007](0007-missing-fields-are-checked-by-server-type.md)):** ответ не той формы — `upstream_invalid` с
  `upstream_status` и `upstream_body`, но без `missing`, отсутствующий `localizedName` читается как поле без перевода,
  а оборванное тело — `upstream_failed` с одним `request`.
- **Поле метаданных, которое `field show` не может показать, — `upstream_invalid` с одним `request`:** id, который не
  встанет сегментом пути, и тип вне таблицы. Тела ответа `Metadata` модуля не отдаёт.

## Следствия

- Ответ `200` не подтверждает строку таблицы, потому что у класса сервер проверяет только кратность. Столбец бандла
  измерен `field show` на поле каждой строки, кроме `StateMachineIssueCustomField`: `bundle(values(name,archived))`
  отвечает значениями у enum, state, version, build и ownedField, `bundle(aggregatedUsers(login))` — пользователями у
  user, а у остальных типов бандла нет. Ключ значения и `$type` тела записи измерены записью значений всех строк
  одним `POST /api/issues` при сидировании дев-инстанса (`dev/README.md`).
