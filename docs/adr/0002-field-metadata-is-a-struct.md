# Метаданные кастом-поля — Go-структура, значение — дерево

Значение кастом-поля приходит под `fields=` вызывающего и остаётся деревом ([ADR-0001](0001-a-response-is-a-tree.md)).
Метаданные ytrack запрашивает своим выражением и получает целиком, поэтому дерево им не нужно.

## Решение

- **Метаданные поля — Go-структура из сравнимых членов**, чтобы второй запрос сверял её целиком.
- **Метаданные проекта берутся одним запросом к проекту** (или к задаче, под `project(…)`). Тип и кратность — из
  `field.fieldType`. Настройки кастом-полей инстанса и `/api/commands` не запрашиваются.
- **Таблица типов выписана вручную, по строке на пару `(valueType, isMultiValue)`**, потому что она нерегулярна.
  Строка задаёт бандл, ключ значения и `$type` тела записи.
- **`$type` в теле записи копируется, а не вычисляется.** Поле, которое стоит на задаче, пишется классом, который
  назвал сервер, а поле, которого нет, — классом из таблицы.
- **Ключ значения зависит от типа:**

  | valueType | ключ значения | как пишется |
  |---|---|---|
  | enum, state, version, build, ownedField, group | `name` | `name` |
  | user | `login` | `login` |
  | period | ISO-8601 из `minutes` | `{"minutes": N}` |
  | date | день ISO-8601 в UTC | полдень UTC этого дня в миллисекундах |
  | date and time | момент ISO-8601 в UTC ([ADR-0003](0003-output-is-one-yaml-document.md)) | миллисекунды |
  | integer, float, string | сам скаляр | скаляр |
  | text | `text`, печатается многострочным текстом | скаляр |

- **Бандл — `values` у enum, state, version, build и ownedField, `aggregatedUsers` у user.** У
  остальных типов источника нет. `bundle.values` пользовательского поля — не те, кого поле принимает.
- **Имена полей ytrack разрешает сам:** по `name`, затем по `localizedName` проекта, без учёта регистра. В тело уходит
  канонический `name`, потому что на любое другое имя сервер отвечает `500`.
- **Имена значений разрешает сервер.** Он исправляет регистр, поэтому проверка записи регистр не учитывает.
- **Многозначное поле пишется целиком:** вызывающий перечисляет весь набор значений.
- **Обязательные поля проверяются до запроса при создании, и `missing_required` называет их все.** Поле, которое
  проект заполняет сам, и поле, скрытое условием, не требуются. Обновление проверяет только поля, которые опустошает.
- **Поле, скрытое условием, ytrack отвергает только при создании**, потому что тогда сервер молча его отбрасывает.
- **Запись читает метаданные с сервера, а не из кэша.**
- **Поля проекта печатаются по `ordinal`, при равенстве — в порядке ответа.**
- **Период печатается из `minutes` как `PT{H}H{M}M`**, потому что `P1D` сервера — рабочий день инстанса, 480 минут.
- **Период и длительность записи времени пишутся только как `{"minutes": N}`**, потому что одно `id` опустошает поле.
- **На вход период принимается только как `PT…H…M`, короче `2^31` минут.** Ноль проверяет сервер.
- **Дата пишется полднем UTC**, потому что он приходится на один день во всех поясах от UTC−12 до UTC+11:59.
- **Допустимые типы работ — набор проекта `plugins.timeTrackingSettings.workItemTypes`**, который ytrack читает с
  задачи. Имя не из набора — `unknown_name` до запроса. Тип отправляется только по `id`.

## Кэш метаданных

- **Каталог принадлежит паре адреса и токена**, потому что права фильтруют и поля, и значения. Файл — на запрос.
  Каталоги `0700`, файлы `0600`, токена в файлах нет. Без домашнего каталога кэша нет.
- **Кэш пишется сразу после получения ответа**, чтобы вызов, кончившийся ошибкой, оставлял кэш тёплым.
- **Кэш подтверждает, но не даёт ошибки.** Всякое расхождение с сервером — промах, после которого метаданные читаются
  заново. `denied`, `rejected`, сбой сети, 5xx и ошибка грамматики `--fields` промахом не считаются.
- **Кэш читает и пишет только `field show`.**

## Следствия

- Ответ `200` не подтверждает строку таблицы, потому что у класса сервер проверяет только кратность. Каждую строку
  держит контрактный тест `field show`, кроме `StateMachineIssueCustomField`.
