# Вход — адрес и токен, взятые целиком

Здесь решено, откуда ytrack берёт адрес инстанса и токен и куда может отправить токен. Главный риск — отправить токен
разработки на рабочий инстанс.

## Решение

- **Адрес и токен берутся целиком из одного источника: окружения или записи входа.**
- **Окружение — источник, если заданы и `YTRACK_URL`, и `YTRACK_TOKEN`.** Пустая переменная считается незаданной.
- **Иначе вход — запись ближайшей области над каталогом вызова.** Глобальная запись действует, только если каталог
  не покрывает ни одна область.
- **Разрешение одно на все команды: `connect(env)` в `internal/cli/credentials.go`.** Исключение — `auth login`, его
  клиент строится из набранного.
- **Документ называет только источник входа**: `auth_from: environment` или `settings`, без переменной, файла и
  записи. Токен не печатает ни один документ.
- **Файл записей — `~/.ytrack/auth.json` (0600) в каталоге 0700**, JSON-массив `{"scope"?, "url", "token"}`. Запись
  без `scope` или с `scope: null` глобальная. `HOME` берётся из `env`, при относительном `HOME` записи не читаются.
- **Файл пишут только `auth login` и `auth logout`, и читается он строго.** Нет файла — нет записей. Всё, чего ytrack
  не пишет, — повреждение, и тогда не используется ни одна запись. Ошибка не называет номер записи. Ошибка доступа от
  системы — не повреждение.
- **Запись файла не меняет чужих записей.** Порядок — глобальная, затем области по байтам. Файл пишется рядом и
  переименовывается поверх старого. Права существующего каталога не меняются. Удаление последней записи удаляет
  файл, но не каталог. Блокировки нет.
- **Область — абсолютный физический путь в написании `filepath.Clean`.** Она покрывает свой каталог и всё ниже по
  целым компонентам: `/a/b` покрывает `/a/b/c`, но не `/a/bc`. Выигрывает самая длинная. Глобальная печатается как
  `global`.
- **Каталог вызова — `PWD` из `env`, если он абсолютный и `os.SameFile` с `.`**, затем без симлинков. Проверка нужна,
  потому что родитель может передать дочернему процессу устаревший `PWD`.
- **Каталог вызова нужен, только если в файле есть область или `auth login`/`logout` вызван без `--global`.** Без
  него глобальная запись не берётся.
- **Адрес — абсолютный `http`- или `https`-URL с хостом, без query и фрагмента.** Query и фрагмент отвергаются, а не
  отбрасываются. Адрес хранится, сравнивается и печатается в одном написании: схема и хост в нижнем регистре, без
  завершающих слэшей. Пароль в userinfo при печати маскируется. Токен с управляющим символом, кроме TAB, непригоден.
- **`auth login` берёт токен только из терминала** и пишет подсказки в него же. Порядок: терминал; место хранения;
  адрес с эхом; токен без эха; `GET /api/users/me`; после `200` — запись. По умолчанию запись получает область
  текущего каталога.
- **Отмена и сломанный терминал дают `upstream_failed`**, потому что кода «остановил человек» в словаре
  ([ADR-0005](0005-an-error-is-a-document.md)) нет.

| Положение | Код | Ключи после `message` |
|---|---|---|
| задана одна переменная из двух; непригодны адрес или токен | `bad_usage` | — |
| входа нет нигде | `denied` | `looked_in`: обе переменные, затем `settings`, если настройки читались |
| файл записей повреждён | `bad_usage` | `file` |
| система не даёт читать, писать или удалить файл | `denied` | `directory` и слова системы |
| `PWD` не называет каталог там, где он нужен | `bad_usage` | — |
| сервер ответил `401`/`403` | `denied` | ключи ADR-0005, затем `auth_from` |
| `auth logout` там, где у каталога нет своего входа; ошибка называет вход, который продолжит действовать | `bad_usage` | — |

## Отвергнуто

- **Keyring.** У агента нет сессионной шины.
- **OAuth.** Нужны браузер и redirect.
- **Адрес из окружения, токен из записи.** Токен уйдёт на чужой адрес.
- **Флаги `--base-url` и `--token`.** Токен попадает в список процессов.
